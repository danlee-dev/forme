# Forme 고도화 순서

이 문서는 공식 기능 조사(FEATURE-RESEARCH.md)를 구현 순서로 연결한다. 모든 기능이 완료됐다는 선언이나 출시일 약속이 아니다.

## 0. 데이터와 로직의 신뢰성 — 이번 변경

- 복수 조건 AND/OR, 숫자·문자열·빈 답변 비교. 클라이언트/서버 공유.
- 참조 문항 삭제 시 조건을 없애고 문항을 공개하는 대신 검토 상태로 유지. 검토 전 게시 차단.
- 전체 CSV 스트리밍, 삭제 문항 데이터 보존, 실패/취소 처리.
- 전체/부분 데이터 범위 명시, 폼 전환 중 오래된 응답 요청 차단.
- 각 요구에 단위·DOM·소유권/API 회귀를 연결한다.

## 1. 설문을 완성하는 입력

기타 직접 입력, 선택지 셔플, 척도 범위/레이블, 날짜 제한, 행렬, 문자열 검증. 업로드·서명은 저장 권한/만료/검사/삭제와 함께 개발한다. 화면만 추가하고 지원으로 표시하지 않는다.

완료: 편집→미리보기→게시→조작→서버 검증→응답/CSV/시트까지 동일한 데이터 의미.

## 2. 흐름과 표현

중첩 조건→페이지 분기/조기 종료→조건부 필수→결과 화면 분기→계산→답변 참조 순서. 페이지 경로와 Back 이력을 단일 엔진에서 계산해야 한다. 새 페이지 점프가 필수 검증을 우회하지 않도록 서버가 실제 방문 경로를 재계산한다.

브랜드 파일·재사용 테마·텍스트/입력 토큰→미디어/열→임베드/팝업→OG→도메인. 사용자 CSS는 별도의 호환성·스코프 기준을 둔다.

## 3. 운영과 연동

서버 검색·전체 집계→시트 OAuth/대상 선택→기존 응답 backfill→자동 재시도/전송 기록→서명 웹훅→그 외 서비스.
Google OAuth는 client ID/secret, 승인된 callback, 최소 scope, 필요 시 앱 검증과 테스트 계정이 필요하다. 현재 제공되지 않은 운영 자격 증명을 임의로 만들거나 연결 성공으로 표시하지 않는다.

이어 작성·수정 링크·메일·PDF·중복 기준·응답 삭제·보유기간·봇 인증은 토큰/만료/동의/실패 복구까지 포함한다.

## 4. 팀·퀴즈·결제

워크스페이스 및 RBAC 후 공동편집·감사. 정답 비공개 서버 채점 후 수동 채점·공개. 결제는 판매자 계정 연결·결제 이벤트 검증·영수증·환불 흐름을 함께 출시한다.

## 5. 검증 가능한 AI와 규모

AI로 생성한 변경은 필드 ID와 로직 참조를 보존한 diff로 제시하고, 적용 전 검사와 undo를 제공한다. 로직 수정은 재현 입력/수정 전후 경로를 보여줘야 한다. 응답 분석은 사용자 동의와 근거 답변을 포함해야 한다. 단순 요약 생성만으로 고유 AI라고 주장하지 않는다.

부하·비용·지연·실패율, 큐/백그라운드 내보내기, 복구 훈련을 검증한다. 현재 단일 스트리밍 CSV가 백만 건 운영을 보장하는 것은 아니다.

## 공통 완료 기준

1. 공식 요구와 Forme 설계 판단을 구분해서 기록.
2. 상태·빈 값·오류·키보드·포커스·모바일·다국어의 사용 흐름 제공.
3. 소유권·서버 검증·다시 시도·중복·취소 검증.
4. 응답·CSV·연동에 데이터 손실 없음.
5. 타입 검사·회귀·빌드·배포·운영 설정 확인.
6. 필요한 외부 계정 설정이 없으면 해당 연결은 ‘미설정’으로 남김.
